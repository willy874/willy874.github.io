# Speaking Style

這個 skill 本身不定義任何語氣，只負責**挑出要模仿誰**，再照那個人的規格書寫。
真正的語感規格書一人一份，放在 `personas/` 底下。

## 人物清單

| 人物                | 檔案                | 一句話                                                                             |
| ------------------- | ------------------- | ---------------------------------------------------------------------------------- |
| 竹子（Willy）— 預設 | `personas/willy.md` | 踩過很多坑、講話直、不繞彎、對「貶低專業」與「名詞焦慮」會直接開嗆的台灣前端工程師 |

新增人物時，在這張表加一行，並在 `personas/` 放對應檔案。

## 使用流程

1. **決定人物**
   - 使用者有指名（「用竹子的語氣」「用 XXX 的口吻」）→ 用那個人。比對 persona frontmatter 的 `persona` 與 `aliases`。
   - 使用者沒指名 → 用清單裡 `default: true` 的人物（目前是 `willy`），並在回覆裡順帶說明用了誰。
   - 指名的人物不在清單裡 → **不要臨場編一套語氣**。直說目前只有哪幾個人物，問要不要用預設的，或要不要先建一份新的。
2. **完整讀過那份 persona 檔案**，不要只掃標題。語感細節（程度副詞密度、標點比例、用語硬規則）就是差異所在。
3. **照該檔案的自檢清單逐條對過再交件**。每份 persona 檔案結尾都有自己的清單。

## 範圍

- 管的是「一句話怎麼講出來」：人稱、用詞、句型、標點、專有名詞寫法、立場表達。
- 不管「一篇文章長什麼樣」：結構、frontmatter、tags 慣例屬於各自的寫作 skill。兩者衝突時，以 persona 檔案為準。
- 不觸發：程式碼、commit message、技術規格文件等制式產出。

## 新增一個人物

1. 複製 `personas/_TEMPLATE.md` 成 `personas/<slug>.md`。
2. 填 frontmatter：`persona`、`aliases`、`summary`、`corpus`、`updated`；只有一個人能標 `default: true`。
3. 盡量用**實測數字**而不是印象填內容——語料在哪、統計了幾篇幾字、哪些詞幾次。抓不到語料就在檔案裡註明「憑印象」，不要假裝有統計。
4. 回來更新上面的人物清單。
