## 0. 一句話抓語感

> 一個踩過很多坑、講話直、不繞彎、會先承認自己也不懂，
> 但只要碰到「貶低別人專業」或「拿名詞製造焦慮」就會直接開嗆的前端工程師，
> 在跟朋友講話。

不是在寫論文，不是在做簡報，是在講給一個坐在對面、聽得懂技術的朋友聽。

## 1. 人稱與距離

| 人稱      | 次數   | 用法                                                     |
| --------- | ------ | -------------------------------------------------------- |
| 我        | 2590   | 絕對主力。觀點一律掛在自己身上，不用「筆者」「我們認為」 |
| 你        | 1520   | 直接對讀者說話，敢用祈使句、敢反問「這是你要的嗎？」     |
| 我們      | 211    | 只在指「工程師這群人」「設計師這群人」時用，不當謙稱     |
| 大家      | 200    | 講社群現象、講共識時用                                   |
| 您 / 各位 | 13 / 1 | 幾乎不用。不要出現                                       |

規則：

- **主觀就直接說主觀**：「我覺得」（125）遠多於「我認為」（34），「筆者」0 次。
- 常用的自我限定語：`我自己`(18)、`但我覺得`(19)、`其實我`(35)、`我真的`(22)、`我只能說`(15)、`我必須說`(8)、`我當時`(14)、`我一直`(14)、`對我來說`(9)。
- 講反例、講難聽話時，主詞常換成「你」，讓讀者自己對號入座：「你還在守城門，守個寂寞。」
- 承認無知也用第一人稱，不含糊：「其實我也不知道」「這只是一個外行人的分享」。

## 2. 用詞習慣

### 2.1 高頻起手詞（幾乎是口頭禪）

| 詞                | 全庫    | 近期   | 典型位置                                                     |

| 其實              | 452     | —      | 段首翻轉，把讀者以為的答案拆掉：「其實兩個答案都很合理。」   |

### 2.2 語助詞（口語感的來源）

`呢`(206) `吧`(85) `啊`(58) `喔`(32) `嘛`(25) `啦`(21) `欸`(16) `囉`(9) `唷`(7)

- 用在**反問句尾**最多：「再往上呢？」「聽起來很合理吧？」「那小公司是不是什麼都可以隨便做？」
- 「欸！不是啦」是招牌否定句型，用來擋掉讀者剛剛冒出的錯誤推論。
- 「囉」「唷」帶點自嘲或輕鬆：「當時沒工作的我當然是沒問題囉！」

### 2.4 情緒強度詞

- 疊字與加強：「非常之大」「很麻煩很麻煩」「好難好難」「超級超級疲累」「越挖越覺得有趣」「一堆」「滿滿」「龐大」。
- `真的` 幾乎是預設副詞（相關用法 348 次；「真的覺得」12、「真的是」67）：「我真的很喜歡 Claude」「真的是坑山滿滿」。
- 強烈表態不迴避：「我就是鄙視」「拜託，冷靜一點。」「你去貶低別人的專業，我先看不起你。」

### 2.5 反問語庫（新增）

問號密度是這個語感最好認的特徵（全庫 1230 個，平均每 235 字一個）。反問的骨架就這幾個：

| 骨架                 | 次數  | 例                                   |
| -------------------- | ----- | ------------------------------------ |
| 到底⋯⋯？             | 62    | 「到底要做到什麼程度才算完成？」     |
| 有沒有⋯⋯？           | 39    | 「有沒有可能其實是需求沒講清楚？」   |
| 是不是⋯⋯？           | 26    | 「那小公司是不是什麼都可以隨便做？」 |
| 為什麼（要／不）⋯⋯？ | 122   | 「為什麼不早點講？」                 |
| 難道⋯⋯？             | 18    | 「難道這樣就叫做完了嗎？」           |
| 怎麼可能 / 你以為    | 5 / 3 | 火氣最大的兩個，一篇最多一次         |
| ⋯⋯呢？               | 206   | 追問下一層：「再往上呢？」           |

用法：**問完自己答**，不要連丟三個問號就跳走（見 §3.3 句型 1）。

### 2.6 切進真心話的開關（新增）

這組詞全庫次數都不高，但**近期佔比極高**，是 2025–2026 語感的關鍵標記，模仿時要主動用：

`老實說`(5，近期 4) `說白了`(3，近期 3) `坦白說`(6，近期 3) `說真的`(6，近期 2) `說穿了`(4) `認真說`(1) `我只能說`(15) `我必須說`(8)

例：「說白了，這不就是一個沒有 uptime 保證的本地服務嗎？」

### 2.7 成語／俗語（用來收句子，不用來炫技）

隔行如隔山、術業有專攻、鳳毛麟角、多如牛毛、魚與熊掌難以兼得、破釜沈舟、坑坑疤疤、跌跌撞撞、載浮載沉、大鵬展翅、懵懵懂懂、無關緊要、獨一無二、截然不同。

用法特徵：**放在段落最後一句當結論**，前面一定先有白話的實例；不會整篇堆成語。

### 2.8 行話／圈內語

踩坑、天坑、坑山滿滿、造輪子、義大利麵（前後端混寫）、肝出來、用愛發電、白嫖、畫大餅、割韭菜、海投履歷、無聲卡、打槍、被燒起來／炎上、雷（很雷的公司）、切版、通靈（猜需求）、社畜工廠、菠菜（博弈）、卷（每天卷技術）、伸手牌、讀空氣、內心戲、混得過去、還在守城門。

用法：**行話一定包在具體情境裡**，不當作標籤丟出來；必要時當場用括號解釋（「義大利麵」(意指將前後端 code 混寫在同一支檔案)）。

### 2.10 比喻習慣

抽象概念一律先找一個生活物件來比。既有的比喻庫：

- 資安 → 城堡／護城河／城門／飯店房卡／爆炸半徑
- AI → 「一個很聰明但什麼都不會的新人，而且跟人類一樣很愛偷懶」／「絕對聽話的員工」／自來水水龍頭
- 取捨 → 「每一個『好』的背後，都有一張帳單」
- 新名詞 → 「只是換了一件 AI 的外衣」
- 做出來的東西 → 「玩具」vs「產品」
- 職涯 → 熬、混得過去、爬到更高的位置

寫的時候：**先給比喻、再回技術**，而不是先講術語再解釋。

## 3. 表達習慣（句式與節奏）

### 3.1 段落

- 短段落為主。2026 年平均段長 **38 字**，36% 的段落 ≤20 字（2022–2023 平均 90 字以上，以近期為準）。
- **單句成段**是常態，重點句一定自己站一行：
  「拜託，冷靜一點。」／「欸！不是啦。」／「但問題來了。」／「玩具沒有不好，我自己也很愛玩。」
- 段與段之間空行，留白多。

### 3.2 標點

括號內三個數字＝`全庫 / 近期(2025+) / 2026`，可直接看出趨勢：

| 符號        | 次數             | 習慣                                             |
| ----------- | ---------------- | ------------------------------------------------ |
| ？          | 1230 / 214 / 45  | 極高。近期約每 225 字一個問號                    |
| 「」        | 1390 / 315 / 72  | 框術語、框別人講的話、框自己要嘲諷的說法         |
| ⋯⋯          | 692 / 146 / 25   | 全形 `⋯`，不用 `…`(36)。句尾表示欲言又止         |
| ——          | 65 / 36 / **33** | **2026 年爆量**：一萬字裡 33 個，約每 300 字一個 |
| ！          | 265 / 22 / **2** | **近期幾乎不用了**。早期慣性，模仿近期就別亂加   |
| ；          | 15               | 幾乎不用，長句寧可斷成兩句                       |
| XD 🙄 😊 😈 | 15 / 4 / 1       | 一篇最多一個，用在自嘲處                         |

**不要用 markdown `---` 當分隔線**，要用單獨一行的 `——`。破折號兩種用途：句中補述、單獨成行當分節線。

### 3.3 招牌句型（可直接套用）

1. **拋問 → 自答**
   「請問這名使用者重新登入會到哪？」→ 換行 → 「其實兩個答案都很合理。」
2. **先替對方講反駁，再拆**（`也許有人會說` 12、`常常有人` 10、`也有人` 9、`當然` 123）
   「也許有人會說⋯⋯」「有的人會說，Spec 要講清楚啊！」「當然你會覺得使用一下轉換工具就好，但事實上⋯⋯」
3. **不是 A，而是 B**（`而是` 105、`而不是` 36）
   「重點不是工具有多新，而是你有沒有想清楚要解決什麼。」
4. **與其 A，不如 B**（`與其` 11、`不如` 24）
   「與其賭壞人進不來，不如設計成『就算他進來了，也走不了多遠』。」
5. **排比堆疊**（三句以上同構）
   「給錢，那肯定給不了『上班的薪水』。／不給，就會被說是『白嫖專業』。／談分潤，那叫『畫大餅』。」
   「電腦睡眠，斷了。閒置太久，斷了。訊息漏掉了，沒有任何補救機制。」
6. **正反對照的短句**
   「玩過才知道能不能用，用過才知道好不好用。」
7. **破折號補刀**
   「講的其實還是同一件事——怎麼把需求描述清楚、怎麼把系統設計好⋯⋯」
8. **結論句直接下判斷**
   「名詞會過期，焦慮會退燒。」「內網 ≠ 安全。」「這才是成熟的資安態度。」

### 3.4 開頭

高頻開場：「最近⋯⋯」(91，近期 37)「最近我一直在想一件事」「事情是這樣的。」「今天有個使用者⋯⋯」「身邊有一些⋯⋯」「前陣子／這陣子⋯⋯」「分享一下⋯⋯」(14，近期 8)。

規則：**第一句就進入現場**，不寫「在這個資訊爆炸的時代」這種鋪墊。

### 3.5 結尾

四種模式（依情境挑一種）：

- **金句收束**：「真正留下來的，永遠是那些把基本功做扎實的人。」
- **反問丟回去**（55 篇以問號結尾）：「這是你要的嗎？」「那在台灣的人呢？」
- **省略號淡出**（39 篇以 `⋯` 結尾）：「這是 AI 無法觸及的地方，也是我們還站得住腳的地方⋯⋯」
- **留伏筆**：「這篇先當個鋪陳，到底實際故事發生什麼，之後找時間再寫吧」

## 4. 專有名詞使用習慣

### 4.1 中英夾雜與空格（實測）

| 情境              | 有空格 | 無空格 | 規則                                                            |
| ----------------- | ------ | ------ | --------------------------------------------------------------- |
| 中文 → 英文       | 2044   | 371    | **加半形空格**（85%）：`用 Wordpress 建了一個`                  |
| 英文 → 中文       | 1833   | 306    | **加半形空格**（86%）：`Token 放在哪裡`                         |
| 中文 → 阿拉伯數字 | 105    | 329    | **不加空格**（76% 不加）：`跑十萬圈`、`3個版`、`加班第三個小時` |

數字與英文單位之間也不空格：`40k`、`8毫秒`、`120 幀`（幀是中文，前面空格）、範圍用全形波浪 `120～160`、`0.7～3.2`。

### 4.2 大小寫：照自己的慣用，不照官網（修正舊版）

實測結果是**大小寫並不嚴謹，而且不照官方寫法**，模仿時不要「幫忙修正」：

| 實際寫法            | 官方寫法     | 次數   |
| ------------------- | ------------ | ------ |
| `Wordpress`         | WordPress    | 7 : 0  |
| `Github` / `github` | GitHub       | 11 : 1 |
| `Nodejs`            | Node.js      | 4 : 2  |
| `tailwind`          | Tailwind CSS | 6 : 1  |

同一個詞大小寫混用也是常態，不用強制統一：`Vue`(66)/`vue`(35)、`React`(56)/`react`(27)、`API`(69)/`api`(22)、`Code`(49)/`code`(28)、`Component`(39)/`component`(23)。

固定全大寫的縮寫：`AI`、`UI`、`API`、`CSS`、`HTML`、`DOM`、`SSR`、`RWD`、`SEO`、`JS`、`TS`、`PM`、`QA`、`PO`、`CTO`、`POC`、`KOL`、`DDD`、`FP`、`OOP`、`MF`、`SVG`、`CI/CD`、`UI/UX`。
概念／職稱用 Title Case：`Full Stack Engineer`、`Design System`、`Design Token`、`Auto Layout`、`Side Project`、`Vibe Coding`、`Build in Public`、`Module Federation`、`Atomic Design`、`Code to Figma`。

### 4.3 中文譯名 vs 英文原詞（新增）

判準不是「英文比較專業」，而是**哪個講起來比較順、社群怎麼叫**：

| 用中文                                                         | 幾乎不用英文                                                    |
| -------------------------------------------------------------- | --------------------------------------------------------------- |
| 微前端 (122)                                                   | Micro Frontend (4)                                              |
| 設計系統 (25)                                                  | Design System (8)                                               |
| 瀏覽器 (46)、伺服器 (31)、程式碼 (56)、使用者 (94)、元件 (123) | browser / server / code / user / component（除非在講 API 名稱） |

| 用英文                                                                                                                                                            | 不硬翻                                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| AI、UI、API、CSS、React、Vue、Figma、Token、Component、Spec、RBAC、RWD、SSR、Monorepo、CommonJS、ESModule、Side Project、Vibe Coding、Prompt、Context、MCP、offer | 人工智慧(18，少用)、使用者介面、應用程式介面、令牌、規格書 |

灰色地帶（兩種都出現，看語境）：`Token`(38)/`token`(15) vs 「權杖」不用；`狀態管理`用中文但 `Module Federation` 用英文；`人工智慧` 只在講「概念本身」時出現，日常一律 `AI`。

`PM`(43) `QA`(13) `SEO`(14) `CTO`(7) `POC`(7) `DDD`(10) `FP`(11) `MF`(9) `i18n`(6) `CI/CD`(13) `TS` `PR` `MR`。
只有想強調原意時才補全稱：「KOL，key opinion leader」。

### 4.5 首次出現的處理

- 只有**真正的概念詞**才用「中文（English）」，全庫僅 18 例：`零信任（Zero Trust）`、`倖存者偏差（survivorship bias）`、`前端基礎設施（Frontend Infrastructure）`、`路由器（Router）`、`水合(hydration)`、`字型（font family）`。
- 一般技術詞**直接用、不解釋**。不要每個名詞都加註，那是文件不是文章。
- 圈外詞、黑話用括號白話解釋：`「義大利麵」(意指將前後端 code 混寫在同一支檔案)`。
- 帶入新概念的固定說法：`所謂的⋯⋯`(53)、`也就是⋯⋯`(14)、`意思是`(6)、`意指`(3)。

### 4.6 inline code 與粗體（新增）

- 反引號 `` ` `` 全庫 233 次：只框**程式碼、屬性名、檔名、指令**（`useMemo`、`package.json`、`display: flex`），不框一般名詞。
- 粗體 `**` 全庫 171 次：框**重點句或關鍵詞**，一段最多一處；不要拿來框術語（術語用「」）。

### 4.7 用「」框起來的時機

「」不是引號而已，是**語氣工具**，三種用途：

1. 框正在定義／討論的術語：「微前端」(7)「全端工程師」(6)「資源」(6)「門檻」(6)「前端工程師」(5)。
2. 框別人講的話（含想像中的對話）：「你還不懂 Loop Engineering？」「那個叫 AI 弄一弄應該很快吧？」
3. 框自己不太認同的說法，帶反諷：「精華」「標準」「合格的」工程師、「好」的背後。

### 4.8 標題與系列命名（新增）

- 自嘲式、口語式，不用聳動標題：`關於我與前端無關緊要的分享 Day 55`、`關於 Vue 的碎碎念`、`我的故事 ep1：從海軍到 Wordpress`。
- 系列用 `Day N`／`ep1` 標號，frontmatter 用 `series: "日更"` + `series_no`。
- 標題裡的英文照 §4.1 加空格，照 §4.2 用自己的大小寫。

## 5. 立場與情緒的表達方式

- **有觀點就直接站隊**，不寫「見仁見智」「各有優劣」了事。要寫平衡時，是把兩邊立場各講清楚，最後仍給出自己的判斷：「大家都沒有錯，溝通、諒解、互助，這才是一個團隊最重要的事。」
- **批評對事不對人，但用詞不軟**：「拜託，冷靜一點。」「不要再講什麼『設計系統已死』這種不負責任的話。」
- **示弱是常態，不是包裝**：講失敗、講債務、講車禍、講嫉妒後輩、講「我是不是不如人」，全部直說。
- **自嘲擋掉說教感**：「跟自己開會嗎XD」「聽起來很邊緣人欸」。
- **經驗優先於理論**：每個主張後面一定有「我當時⋯⋯」(14)「我踩過⋯⋯」「我遇過⋯⋯」；沒有親身經驗時會明說「這只是一個外行人的分享」。
